# Папка службы: права доступа и ошибки установщика

Подробное руководство к скрипту [`Add-Admin-as-Folder-Owner-for-Happ.bat`](../Add-Admin-as-Folder-Owner-for-Happ.bat).

Коротко: скрипт нужен, если программа со службой `LocalSystem` поставлена в папку, созданную вручную. Он делает владельцем `Administrators` и оставляет `Users` только чтение — этого достаточно, чтобы установщик зарегистрировал службу. Родительская папка не меняется.

## Какую проблему решает

При установке Happ (а также любой другой программы, которая регистрирует службу Windows под `LocalSystem`) установщик может отказаться работать:

```
Owner is outside the trusted system principals.
Access control entry grants rights outside the trusted system principals.
```

В интерфейсе установщика это выглядит как «Установщику не удалось проверить права доступа к папке», а после установки — «Служба Happ Client недоступна (ошибка 1060)».

## Почему так происходит

Служба под `LocalSystem` — это процесс с правами `SYSTEM`. Windows (Service Control Manager) не разрешает регистрировать такую службу, если её `.exe` лежит в папке, которую может изменить обычный пользователь, или если владелец папки не входит в доверенные субъекты. Типичные причины:

- папку создал обычный пользователь, поэтому её владелец — SID пользователя, а не `Administrators`/`SYSTEM`;

- папка скопирована с другой машины или из другой установки Windows (владелец — «чужой» SID, который уже не резолвится);

- папка наследует `Users: Modify` от родительского каталога (например, `D:\Programs`, созданного из-под пользователя).

## Где ставить программу со службой

Если есть выбор, ставьте её в `D:\Program Files\<Имя>` или `C:\Program Files\<Имя>`. Такую папку создаёт сам установщик, и он сразу делает владельцем `Administrators`, а `Users` оставляет только чтение — служба `LocalSystem` регистрируется без ошибок, и этот скрипт не нужен.

Скрипт нужен, когда программа поставлена в папку, созданную вручную (например, `D:\Programs\Happ`): у такой папки владелец — пользователь, а права приходят по наследству от `D:\` вместе с записью для `Users`.

## Что делает скрипт

Скрипт приводит **только указанную папку** к состоянию, которое Windows принимает:

| Свойство | Значение |
| --- | --- |
| Владелец | `BUILTIN\Administrators` |
| ACL | `SYSTEM` — полный доступ, `Administrators` — полный доступ, `Users` — чтение и выполнение |

Родительская папка не изменяется. Если целевой папки ещё нет, скрипт создаст её с правильными правами — установщику останется только положить туда файлы. Службы, реестр и скачивание чего-либо скрипт не трогает.

## Использование

Перетащите папку на `.bat` или запустите из консоли:

```
:: подготовить папку (режим по умолчанию)
Add-Admin-as-Folder-Owner-for-Happ.bat "D:\Programs\Happ"

:: только проверить, ничего не меняя (права администратора не нужны)
Add-Admin-as-Folder-Owner-for-Happ.bat "D:\Programs\Happ" --check

:: откатить строгие права и вернуть наследование
Add-Admin-as-Folder-Owner-for-Happ.bat "D:\Programs\Happ" --restore
```

| Режим | Что делает | Нужен админ |
| --- | --- | --- |
| `prepare` (по умолчанию) | владелец `Administrators`, ACL `SYSTEM:F / Administrators:F / Users:RX` | да |
| `--check` | показывает владельца и наличие записи у недоверенных субъектов | нет |
| `--restore` | забирает владение и рекурсивно возвращает наследование от родителя (папки и файлы) | да |

`prepare` и `--restore` сами запрашивают повышение прав (UAC). Коды возврата: `0` — папка пригодна для службы, `1` — ошибка, `2` — неверные аргументы.

`--restore` нужен, если права папки уже меняли вручную или файлы скопированы с другого диска: он забирает владение и рекурсивно возвращает наследование. Строгие права папки службы при этом снимаются, поэтому перед следующей установкой запустите `prepare` ещё раз.

## Как проверяется результат

Отчёт не зависит от языка Windows: скрипт сравнивает **SID** (`S-1-5-32-544`, `S-1-5-32-545`, …), а не локализованные названия групп, и ищет любого недоверенного субъекта (`Users`, `Authenticated Users`, `Everyone`, `INTERACTIVE`, `SERVICE`, `NETWORK`) с правом записи. Готовая к установке папка выглядит так:

```
Trusted owner         : yes
Write access, untrusted: none
RESULT: OK - this folder is safe for a LocalSystem service binary.
```

## Служба всё равно падает с ошибкой 5

Если папка вне `Program Files` продолжает упираться, самое быстрое решение — переустановить программу в `D:\Program Files\<Имя>`: установщик создаст папку с правильными правами сам, и вопрос закроется. Пользовательские настройки в `%LOCALAPPDATA%` при этом обычно сохраняются.

## Требования

Windows 10/11 (работает и на 8.1+), встроенный PowerShell 5.1, права администратора для `prepare` и `--restore`.
